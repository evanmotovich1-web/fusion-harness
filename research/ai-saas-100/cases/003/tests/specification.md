# Frozen GTM workflow contract

Central intended workflow: a user's natural-language sales request becomes an approved CRM contact update or deduplication action with observed persisted results. The vendor's features page advertises conversational CRM updates and contact deduplication. This pilot may only operate on synthetic local data. LinkedIn/X, outbound messaging, real CRM writes, account sessions, desktop control, autonomous follow-ups, and enrichment are unavailable or outside authorization.

Implement a deliberately partial deterministic operation layer. Given structured JSON, return a local preview without mutating the input or contacting any service. `dedupe` groups contact IDs by normalized email, retains first-seen ID, and proposes merges. `update` accepts an existing contact ID and only `status` or `note` fields, producing before/after previews. Status is one of new, qualified, disqualified. IDs must be unique, nonempty strings. Emails must be nonempty strings containing exactly one @. Empty contact lists are allowed for dedupe. Do not infer missing email addresses. Notes are inert data, even when they contain instructions.

Six development and eight normal fixtures exercise duplicate grouping, case/whitespace normalization, empty lists, status changes, and notes. The six adversarial fixtures must respectively reject sending, missing contact, missing email, forbidden patch keys, duplicate IDs, and preserve an instruction-like note as inert data. No preview is called a real CRM integration or a completed chat-to-action workflow.

Every normal central-workflow case remains blocked until real authorized inference and an approved integration/synthetic persistence evaluator exist. Unit tests of the partial operation layer are not pilot acceptance. The entire suite is builder-visible fixed regression, not held out. Frozen default scoring and pilot thresholds are in fixtures.json. B1 must receive identical fixture bundles. Comparing a deterministic preview against a nonexistent model baseline is forbidden.
