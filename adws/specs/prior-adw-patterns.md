## Complete SSSF script inventory

Notation: **E** = engineer request phase, **A** = agent, **C** = deterministic code, **G** = C owned by git. Shared gate names: **artifact** = declared artifact existence, **nonempty** = nonempty files, **citation** = citation syntax in logical checklist items, **diff claim** = claimed changed paths exist, **verdict** = approval agrees with blocking/unmet findings. These names describe the actual checks, not stronger guarantees.

Shared bounds: JSON correction budget is two retries. Gate retries are `PhaseParams.retries`, independent of workflow repair loops. Review loops default to **8 review rounds**, with at most 7 intervening revisions, overrideable by `ADW_MAX_REVISIONS >= 1` with no fixed upper maximum. `/Users/evanmotovich/code/sssf/adws/adw_modules/loops.py:1-24`.

## Per-agent telemetry shape

The implementation should normalize these records while preserving source and missingness. This is a **recommended builder contract**, not a claim that all fields already exist in every prior workflow.

| Code | Record | Required fields and interpretation |
| --- | --- | --- |
| T1 | Run | schema version, run id, workflow id/version/hash, original request reference, effective config reference/hash, source revision, started/ended timestamps, run status, acceptance status and reason, artifact index. Keep execution success separate from accepted/delivered. |
| T2 | Phase attempt | run id, phase id/name/kind/owner, attempt, dependencies, started/ended timestamps, duration, execution status, error, declared outputs, gate ids/results. Agent identity includes slot/role, coding harness, effective provider/model, thinking, session id and configured tool allowlist. |
| T3 | Agent tool call | run/phase/agent/attempt attribution, call id, tool name, sanitized args or reference, start/end, duration, completion status, `ok`/error, retained result reference/snippet. Count once per call id in the attribution scope. Interrupted starts must remain incomplete, not disappear or pass. |
| T4 | Code operation | Operation id and name, argv, cwd, start/end, duration, return code, exit reason, passed flag, stdout/stderr references and hashes. Do not invent an agent/tool name to fit code receipts into agent totals. |
| T5 | Agent usage | input/output/cache-read/cache-write/reasoning/total token buckets, cost buckets/total, currency, cost source, completeness and latest context occupancy/window. Accumulate every attempt once, including partial-failure usage. Never sum latest occupancy as if it were all billable usage, or double-count reasoning already included by provider totals. |
| T6 | Summary | Per-agent tool-name counts, tool-call count, tool-error count, incomplete calls, agent duration, token totals and reported cost. Preserve `unknown` when absent. Run cost must describe whether it includes agent, classifier, nested and failed-attempt lanes. |

Existing SSSF normalizes completed Pi tool calls with call id, tool, arguments, `ok`, result snippet, timestamps and duration, then attaches agent/phase identity in the forwarder. ## What “perfect for the request” can objectively mean

Every original requirement must map to a **phase, typed output, gate and verifier**, or to an **explicit blocker**. This is measurable coverage, not guaranteed perfection from a model.

| Code | Acceptance obligation | Reject when |
| --- | --- | --- |
| A1 | Preserve original request and resolve consequential ambiguity before implementation. Record requirement ids and user-visible assumptions. | A goal is silently narrowed, different input is reused under an old run, or a missing choice changes meaning/safety. |
| A2 | Map every requirement to an execution phase, expected artifact, concrete gate, verifier and evidence reference. | Any requirement is absent, only repeated as prose, dependent on an unsupported capability, or marked met without evidence. |
| A3 | Validate runnable structure and capabilities before spend: registered roles/models/tools, dependency graph, output schema, operation binding, input availability and limits. | Unknown tool/model/operation, invalid graph, unresolvable input, invalid auth or unsupported runner capability remains. |
| A4 | Verify output bytes and requested semantics on the final mutation state with focused positive, negative and refusal cases. | Green checks predate a write, only fixture data satisfy a live ask, or tests exercise another project. |
| A5 | Require an independent requirement review and close all blocking findings within a bounded repair budget. | Review approval contradicts unmet criteria, rejects the plan but execution ignores it, or repairs exhaust/no-progress. |
| A6 | Record actual tool errors, duration, model identity, tokens and cost with missingness, partial failures and source provenance. | Fake counts, assumed zero cost, unrecorded failures or unexplained aggregate billing are presented as proof. |
| A7 | Treat save, validate, execute, accept and publish as separate states. Persist blocked/unavailable outcomes and leave artifacts inspectable. | Saving a recipe is called a successful run, an accepted run is called deployed, or generated instructions gain commit/push/outreach authority. |

A suitable requirement record is:

```json
{
  "id": "req-1",
  "request_text": "The user's exact requirement",
  "phase_id": "phase-name",
  "output": "artifact-path",
  "gate": "registered-gate-id",
  "verifier": "focused-check-id",
  "evidence": ["run-artifact-reference"],
  "status": "verified-or-blocked",
  "blocker": null
}
```

This is proposed acceptance data, not executable configuration or permission. The directly reusable precedent is distillation's `asked && !met` rejection and homecare's current-byte acceptance, reinforced by the retained review that explicitly named missing original asks. The builder should emit an honest, testable workflow and its blockers, never promise unmeasured perfection.
