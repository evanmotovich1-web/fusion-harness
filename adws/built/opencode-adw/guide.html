Local workflow · quick guide

OpenCode ADW

A deterministic runner for a scoped build, explicit checks, a fresh read-only review, and a recorded handoff.

Installed locally · workflow and per-agent model pickers

Start in OpenCode

  1. Restart OpenCode to load the installed native configuration.
  2. Open the native agent picker and select opencode-adw.
  3. Use a command below. Include the target repository, requested change, and acceptance criteria.

Installed runtime: ~/code/fusion-opencode-adw/adws/built/opencode-adw/runtime.py. The installer manifest connects the native agent and desk to this same copy.

Native commands

/oc-build

Implement the request, run focused checks, then review.

/oc-takeover

Recover context through the existing session bridge and recent handoffs, then continue. Report any fallback.

/oc-review

Inspect against requirements without repairs. Checks need an explicit, side-effect-free request.

/oc-status

Read recorded run and capture states; optionally append a run ID.

Use the live desk

Open the simple OpenCode workspace. Pick a repository, choose Build & review, Review only, or Continue previous work, and enter your task. Choose a model on each agent card, then press Run.

The list covers discovered local checkouts, not every remote GitHub repository. Expand discovery coverage to see scanned roots and limits.

Test commands and diagnostics are under Advanced. Review only shows one Reviewer card; the other workflows show Builder and Reviewer.

What executes

  1. Build
  2. Checks
  3. Fresh review
  4. Report / handoff

Checks run only when supplied; omitted checks are SKIPPED. A failed check or review fails the run.

Each agent has its own model dropdown, grouped by OpenAI, DeepSeek, GLM, Grok and Gemini. Existing keys/logins are reused. The recorded default remains openai/gpt-6.1-sol until you choose another model.

Builder edits files; checks are code; Reviewer inspects read-only in a separate session. Recorded activity shows the models and state of the selected repository's actual runs.

Native commands request bounded result capture through the existing vault. CLI capture is a separate step; verify its receipt.

The runner leaves code uncommitted. Initial release: toolkit #28 and desk #32. The repository-picker correction is installed locally.
