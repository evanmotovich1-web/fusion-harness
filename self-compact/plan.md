The extension must load on its own in Pi and be explicitly loaded into Evan's application-owned session. It must not modify Fusion's temporary workers. ## Decoded ask and sources

The user approved building the Evan terminal agent and added “use the self-compact thing.” Implement the standalone Pi self-compaction behavior described in `self-compact/prompt.compound.md` and `self-compact/SELF_COMPACT_AGENT_BRIEF.md`, then integrate it into Evan. Pi already has persisted compaction entries, automatic compaction, `/compact`, `ctx.compact()`, and `session_before_compact`/failure hooks (installed Pi `docs/compaction.md`; `docs/extensions.md`). Reuse these APIs instead of replacing session history. Generated summaries are never authorization or the source of worker/approval state.

The two project briefs disagree on flag spelling: the brief's launch example uses plural `--compactions-soft-at` and `--compactions-at`; the compound prompt also says singular `--compact-soft-at` and refers to `compact-at`. **Canonical flags** are the brief's plural pair plus `--compact-buffer` and `--compact-prompt`. Register singular `--compact-soft-at` and `--compact-at` as aliases. Reject conflicting values across an alias and its canonical flag; do not silently choose one.

## Deliverables and boundaries

1. `extensions/self-compact/self-compact.ts`, plus only small helpers in the same directory if needed: standalone Pi extension that registers flags and a recovery/manual command, renders the context meter, manages thresholds, and invokes Pi's compaction lifecycle. Never require `fusion-harness.ts` to load it.
2. `extensions/self-compact/self-compact.test.ts`: offline unit/integration tests with mocked Pi API, no model calls. Keep the test alongside the extension so self-compact implementers do not need to read unrelated `specs/*` or `apps/*` files.
3. `.pi/self-compact/USER_SOFT_SELF_COMPACT.md`, `.pi/self-compact/USER_PROMPT_SELF_COMPACT.md`, `.pi/self-compact/USER_PROMPT_COMPACTION_MESSAGE_.md`: editable soft notice, warning, and compaction prompt templates. Read them from the active project root and provide an explicit fallback/error when absent; do not treat prompt text as policy or tool approval.

Other builders own `tools/evan/`. Do not edit `justfile`, `planf1/plan.md`, the alternative `/fh-debate` spec, other extensions, or existing dirty/untracked paths. Do not read unrelated `specs/*` or `apps/*` as part of the self-compact implementation. The app owner loads the standalone extension only after focused checks pass.
