# Proposed `/fh-debate` evolution plan (2026-09-25)

**Status: alternative proposal, not the established deliverable or an approved implementation specification.** One collaboration review reports that preceding conversation debated building Evan Agent, but cites no debate transcript or final plan. A separate scope review found no repository source connecting “FH debate plan” to Evan Agent and traced the proposed Evan application build to agent-authored proposals. ## Current contract

- `/fh-debate` defaults to three rounds, caps the count at ten, requires at least two, and prepares one knowledge packet before spawning the configured slots. The packet is injected into opening prompts only; later prompts use the prior round's answers and resumed child sessions (`extensions/fusion-harness/modules/cmd-readonly.ts:19-30,87-114,119-145`).
- Each succeeding round admits only successful participants and halts if fewer than two remain. Successful participants without a resumable session reference cannot advance. The command writes individual round files, a final panel of individual closing opinions, and a run summary on normal completion; `finally` ensures a fallback summary on early return (`extensions/fusion-harness/modules/cmd-readonly.ts:119-176`).
- Peer opinions are attributed and delimited; failed participants get unavailable markers. If other participants' *successful answer text* exceeds the 60,000-character handoff budget, prompt construction refuses rather than silently truncating it. That check does not count framing or failed-participant markers (`extensions/fusion-harness/modules/prompt-library.ts:19,224-237`). Rebuttal and closing prompts treat peer text as untrusted material. Closing explicitly has no judge or merge (`extensions/fusion-harness/prompts/USER_PROMPT_DEBATE_REBUTTAL.md:1-7`, `extensions/fusion-harness/prompts/USER_PROMPT_DEBATE_CLOSING.md:1-7`).
- Debate child turns receive `READONLY_TOOLS` (`read,grep,find,ls`), but the **host** can still create lane worktrees and branches, copy untracked files, and commit carried changes to a lane branch before the child runs. “Read-only” describes child tools, not an absence of Git or artifact writes by the harness (`extensions/fusion-harness/modules/runtime.ts:16-19`, `extensions/fusion-harness/modules/cmd-readonly.ts:114-145`, `extensions/fusion-harness/modules/lanes.ts:208-250`). The closing panel presents individual answers, not a consensus verdict (`extensions/fusion-harness/modules/tui.ts:393-409`).

## Gaps and risks, not new product requirements

1. **Observed coverage gap:** Existing debate checks assert source strings and prompt text, not executed round transitions, rendered handoffs, or output files (`extensions/fusion-harness/tests/orchestration-contract.test.ts:48-59`, `extensions/fusion-harness/tests/knowledge-orchestration.test.ts:25-54`). Prompt interpolation silently replaces an unknown placeholder with an empty string, so a template change could lose content without a behavioral check (`extensions/fusion-harness/modules/prompt-library.ts:53-56`).
2. **Observed evidence gap:** Early exits for too few survivors, oversized handoffs, and missing sessions display errors, but the fallback summary does not record a machine-readable cause, failing round, or packet hash (`extensions/fusion-harness/modules/cmd-readonly.ts:119-136,151-175`). This is an observability proposal, not evidence that normal closing is wrong.
3. **Inferred error-path risk, not reproduced:** A rejected child/artifact-write promise could cause `Promise.all` to reject while sibling children are still active. The `finally` block then releases stop handling without visibly settling those siblings (`extensions/fusion-harness/modules/cmd-readonly.ts:139-148,170-176`). A controlled failure test must establish the behavior before changing cancellation logic.

## Non-goals and unresolved questions

Children remain limited to `read,grep,find,ls`; peer text remains untrusted; opinions stay complete or fail explicitly when over budget; the same retrieved packet is injected at opening only; successful participants need resumable sessions for later rounds; final opinions remain separate with **no judge, merge, or automatic implementation**. This plan does not authorize expanded file access, new Git publication, installation, commits, deployment, or an Evan application.
